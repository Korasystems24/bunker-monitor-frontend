# CLAUDE.md — Правила проекта (загружается автоматически)

Полное ТЗ: `PROMPT.md`. При начале нового этапа читай его целиком.

## Что строим

Фронтенд (React) для мониторинга бункера на горно-обогатительном предприятии.  
Радарный уровнемер УЛМ-3D-64: 64 луча = 8 осей (A–H) × 8 позиций.  
Бэкенд — Python/FastAPI — **ещё не готов**. Работаем против мок-сервера.

## Стек (не менять без явного решения)

- Vite + React + **TypeScript strict** (никаких `any` для API-данных)
- Состояние сервера: **TanStack Query** (polling, кэш)
- Стили: **Tailwind CSS**, тёмная тема по умолчанию
- Графики 2D: **Recharts** (ECharts — только с обоснованием)
- 3D (этап 3+): **react-three-fiber** + **@react-three/drei**
- Линт/формат: ESLint + Prettier — нарушений быть не должно

## Архитектурные правила

- **Multi-bunker-ready с первого коммита**: `bunker_id` в роутинге и API-вызовах, даже пока бункер один.
- **Фронт не вычисляет геометрию лучей** — координаты приходят из `GET /geometry`. Fallback-раскладка (8 осей × 45°, равномерный радиус) — только для разработки без бэкенда.
- Бизнес-логика (`parseStatus`, `isBeamReliable`, цветовые шкалы, интерполяция) — в `lib/`, не в JSX.
- Мелкие переиспользуемые компоненты; состояние сервера — в React Query, не дублировать вручную.
- Интервал polling и прочие параметры — в конфиге, не хардкодить.
- Никакого `localStorage/sessionStorage` без явной необходимости.

## Данные: критически важно

```
status — строка с флагами через запятую: "TooShort, NotUsed, WeakSignal"
Парсить: split(",").map(s => s.trim())
```

- `height = 0` **не означает «руды нет»** — смотри на статус. Использовать `isBeamReliable(statusFlags)` везде.
- Единицы (`avg_level` — м, `volume` — м³, `mass` — т) — **константы, не хардкодить подписи**.
- `ts` — ISO-8601 UTC; показывать в локальном времени, хранить/сравнивать в UTC.
- `beam_name`: `parseBeamName("H6") → { axis: "H", position: 6 }`. Внешние позиции (большие цифры) = боковые зоны.

## Структура папок

```
src/
  api/        — fetch-функции, React Query хуки
  components/ — переиспользуемые UI-компоненты
  features/   — экраны/фичи (dashboard, history, 3d...)
  lib/        — чистая бизнес-логика (без JSX)
  config/     — константы, параметры polling, единицы измерения
  types/      — TypeScript-типы (Measurement, Beam, BunkerGeometry...)
```

## Открытые вопросы (фиксировать в README)

- Точная ориентация осей A–H по азимуту (0° = ?): уточняется из данных Конфигуратора.
- Единицы `volume` и `mass`: принято м³ и т — зафиксировать как допущение.
- Критерий детекции налипаний: определяется заказчиком, параметр в API.

## Визуальные требования

- Диспетчерский вид: контрастный, читаемый с настенной панели.
- Статус луча — **не только цветом**: дублировать иконкой/паттерном (важно для дальтоников).
- «Плохие» лучи (ненадёжные по статусу): приглушение + штриховка, тултип со списком флагов, не участвуют в цветовой шкале высоты.
- Состояния загрузки/ошибки/пустых данных — skeleton + понятные сообщения, не белый экран.
